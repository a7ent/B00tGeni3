Bug found and fixed in this phase
  Symptom: second swap failed, "Access Denied". Every File->Delete from the tool returned Success, deleted nothing.
  Cause (read in source, then confirmed at runtime): OpenCore's OcVirtualFsLib hooks gBS->HandleProtocol and
    LocateProtocol (Library/OcVirtualFsLib/VirtualFs.c:116-117, enabled from OcMainLib/OpenCoreKernel.c:1542).
    Files opened through that wrapped file system get VirtualFileDelete, which calls Close, not Delete
    (Library/OcVirtualFsLib/VirtualFile.c:141).
  Fix: the tool gets EFI_SIMPLE_FILE_SYSTEM_PROTOCOL with gBS->OpenProtocol(..., GET_PROTOCOL), which is not hooked.
  Before: bench/logs/20261114-183455-fstest2.png - 6 control cases, all "delete Success" then file still present.
  After:  bench/logs/20261114-213359-fstest3.png - same 6 cases, all reopen = Not Found; host raw dump shows
          PRE.TMP and PLAIN.TMP as deleted entries.
  Not verified: that OpenShell's rm worked because the shell uses OpenProtocol (shell source not read).
