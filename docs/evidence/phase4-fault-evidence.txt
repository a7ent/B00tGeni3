RESIDUAL RISKS (not fixed, oTR-DaRkNeSs to decide)
  - A cut can leave FAT damage (orphan clusters, junk entries) in EFI\OC or EFI\OC\B00tGeni3. On a Mac the fix
    is Disk Utility First Aid or fsck_msdos on the ESP. The tool does not check or repair the file system.
  - The backup and active.txt are written into the folder that holds known-good, so damage from a cut lands
    next to the failsafe. Options: move those writes to a subfolder, and/or show a red "last swap was
    interrupted" warning when leftover temp files exist. Neither built.
  - Repeated swaps on an already damaged FAT (series 1) ended with the variant folder unreadable. With 0.8f
    the tool would keep any variants it could read, but a folder that cannot be listed at all still leaves
    nothing to pick; OpenCore itself kept booting.
  - Firmware FAT drivers differ; all of this is OVMF's. Real hardware not tested.
